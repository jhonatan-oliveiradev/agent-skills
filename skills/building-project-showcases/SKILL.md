# Building Project Showcases

Create a durable presentation that helps a stranger understand the project and inspect the work. Use the audience, verified claims, and links from `preparing-project-launch` when available; otherwise inspect them before publishing.

## Workflow

1. Choose one primary reader and decision: try the product, install it, evaluate the engineering, or contribute. Confirm what exists now, its release state, and which visuals may be shared.
2. Extract the problem, who experiences it, the actual product path, the most distinctive interaction, meaningful implementation decisions, and the result that can be demonstrated. Separate observed outcomes from goals and future plans.
3. Build a narrative around real evidence: concise opening, a clear demo (entry → action → result), two or three specific decisions and trade-offs, proof close to each claim, and one clear next action. Show usable interface captures or product footage rather than abstract feature cards.
4. Adapt that story to its surface: a portfolio case study can explain process and decisions; a README should get contributors to the install or demo quickly; a product page should answer audience needs and objections. Reuse `building-conversion-product-pages` for full page architecture and `writing-conversion-copy` for persuasive offer copy when those are the actual deliverables.
5. Prepare an asset and link checklist: accessible image descriptions, caption or transcript for video when needed, mobile-safe crops, working install/demo/repository URLs, credit for borrowed assets, and a valid social preview. Review in the rendered surface at small and large widths.
6. Ask a fresh reader to describe what the product does and the action they would take. Revise any point where the visual story suggests a capability the released project does not have.

## Output

Return the chosen format, page or README outline or implemented artifact, visual shot list, validated claims with sources, CTA and links, and any evidence still missing. Avoid presenting a concept mockup as a working product or fabricated testimonials as proof. Video production belongs to `brag-slim`; campaign timing belongs to `planning-launch-distribution`.
