# Building Brand Guidelines

## Core principle
Brand guidelines are an operating manual for consistent decisions, not an archive of presentation slides. Document the minimum rules and examples needed for another person to reproduce the identity without guessing.

## Guideline workflow
1. Define the audience and use cases for the guide. A small internal team, distributed marketing organization, partners, and vendors need different levels of detail.
2. Start with the brand principles that explain the system. Rules are easier to apply when users understand the strategic intent behind them.
3. Document identity assets and hierarchy: primary/secondary marks, wordmarks, clear space, minimum sizes, background behavior, and approved asset sources.
4. Define typography as a working system. Include families, roles, hierarchy, weights, fallback behavior, licensing or availability constraints, and representative layouts.
5. Define color by role, not just swatch. Record values for relevant media, accessible text/interface combinations, and cases where color must not be the only carrier of meaning.
6. Document composition and supporting language: grids, spacing, graphic devices, imagery/illustration treatment, iconography, motion principles, and any recurring production patterns.
7. Connect verbal guidance. Summarize or link the approved voice, messaging hierarchy, terminology, and tone rules rather than duplicating conflicting copy standards.
8. Show both correct and incorrect applications using realistic examples. Prioritize mistakes people are actually likely to make.
9. Add operational guidance: file naming, source-of-truth locations, ownership, version/date, exception process, and how changes are approved.
10. Test the guide by giving it to someone who did not create the identity and asking them to produce a representative artifact.

## Guideline quality checks
The guide should let a collaborator answer:
- Which asset should I use here?
- How should this hierarchy behave at this size?
- Which color combinations are permitted for meaningful text or interface states?
- What is flexible versus invariant?
- Where is the canonical asset?
- Who decides when a new pattern becomes part of the system?

## Avoid
- hundreds of decorative pages with little production guidance;
- undocumented “designer judgment” for recurring decisions;
- logo misuse examples without rules for the rest of the system;
- inaccessible color pairings hidden behind brand aesthetics;
- stale PDFs that have no owner, version, or source of truth.

## Verification
Run a guideline usability test: ask a new collaborator to create one routine and one edge-case artifact using only the guide and canonical assets. Record where they must guess; those gaps are missing rules or examples.
