# Agent Skills Studio — Codebase Intelligence Real-Use Evidence Design

**Date:** 2026-09-02

**Baseline:** `main` at `72c95adfa584f4ea81dd185ced4c969d02f2c2e0` (`1.0.0-rc.2`)

## Purpose

Close the explicit RC2 evidence gate for `codebase-intelligence` with inspectable real-project evidence, without promoting the Studio to Stable in the same tranche.

The qualifying case is a real ROCKET maintenance slice that used all five Codebase Intelligence methods to determine whether a deprecated Cosmic SDK/write path could be removed safely while preserving the Payload-first public runtime, local fallbacks, and historical read-only migration compatibility.

## External evidence boundary

ROCKET is private. The public Studio must not expose private repository, PR, commit, or Actions URLs. As with the existing Rocket real-use record, the Studio may publish:

- public-safe project identity (`Rocket UNESP`);
- method names and decision/result narrative;
- opaque PR/commit/workflow identifiers supplied by the project owner for auditability;
- public Studio-hosted source and QA anchors.

## Codebase Intelligence methods represented

No CodeGraph runtime was callable in the execution environment. Per the shipped method contracts, no runtime was installed or initialized. The case exercised the verified repository-inspection fallback and progressive context expansion.

## Real-use qualification

The case qualifies because it produced a real maintenance decision and change rather than a synthetic demonstration:

- investigation narrowed a broad "remove Cosmic" idea to one obsolete SDK/write path;
- false positives in migration code and CDN configuration were explicitly rejected;
- a regression contract established RED before implementation;
- the deprecated `cosmicjs@5.0.5` package, `populate` script, and writer were removed;
- historical Cosmic migration via native `fetch()` was preserved;
- the package lock was regenerated by npm;
- final ROCKET CI passed install, Payload type drift, full tests, lint, typecheck, and production build;
- no schema, database, public runtime loader, migration semantics, or visual/UI implementation changed.

## Stable-readiness semantics

RC2 currently has an additive gate:

```json
{
  "status": "collecting-rc2-evidence",
  "requiredRealUsePacks": ["codebase-intelligence"],
  "validatedRealUsePacks": []
}
```

After this case is recorded and verified, update the same RC2 manifest to:

```json
{
  "status": "ready-for-stable-review",
  "requiredRealUsePacks": ["codebase-intelligence"],
  "validatedRealUsePacks": ["codebase-intelligence"]
}
```

Observed real-use totals become:

```json
{
  "realUseCases": 4,
  "distinctProjects": 3,
  "activePacksRepresented": 5
}
```

`distinctProjects` remains 3 because Rocket is already represented. `activePacksRepresented` increases from 4 to 5 because Codebase Intelligence is newly represented.

Existing public-surface evidence remains unchanged; this case validates the new pack-level gate, not microsite/catalog/installer/ChatGPT distribution surfaces.

## Stable boundary

This tranche does **not**:

- change `VERSION` or any package/catalog version to `1.0.0`;
- create a Stable tag or release;
- claim the Stable promotion decision has already been made.

It only restores the candidate to `ready-for-stable-review`. Stable promotion remains a separate review and release tranche.
