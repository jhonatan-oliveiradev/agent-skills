# Stable 1.0.0 promotion — implementation plan

**Goal:** Promote the merged, evidence-qualified `1.0.0-rc.2` Studio to Stable `1.0.0` with no canonical skill behavior changes.

**Base:** `main` after PR #56 merge.

## Task 1 — Establish RED Stable contracts

- [ ] Update `scripts/release-readiness.test.mjs` to require six synchronized Stable version owners, including `apps/web/package-lock.json`.
- [ ] Require schema-v4 Stable readiness state with `promotedFrom: "1.0.0-rc.2"` and preserved evidence totals.
- [ ] Update `scripts/codebase-intelligence-pack.test.mjs` current-version expectations from RC2 to Stable.
- [ ] Update localized project-page tests so the newest release is `1.0.0` on `2026-09-02` and RC2 remains historical.
- [ ] Open a Draft PR and capture canonical RED evidence before production metadata changes.

## Task 2 — Promote release metadata mechanically

- [ ] Set the six release owners to `1.0.0`.
- [ ] Synchronize all 54 skill metadata + 11 pack metadata versions to `1.0.0` without changing canonical `SKILL.md` content.
- [ ] Regenerate `catalog/generated/catalog.json` with the official generator.
- [ ] Sync `apps/web/src/generated/catalog.json` with the official web sync script.
- [ ] Update any current-version test assertions exposed by CI; never rewrite historical docs or release entries.

## Task 3 — Publish Stable release state

- [ ] Advance `release/stable-readiness.json` to schema v4 / `status: "stable"`, preserving all evidence.
- [ ] Add the new Stable entry at the top of `CHANGELOG.md`.
- [ ] Add localized `1.0.0` release entries at the top of the public web changelog while preserving RC2/RC1 history.

## Task 4 — Final canonical verification

- [ ] Remove every temporary materialization workflow before final evidence.
- [ ] Run the canonical `Validate skills` workflow on the exact clean PR HEAD.
- [ ] Require Ubuntu and Windows full GREEN across root tests, validate, web tests, typecheck, lint, build, and platform installer smoke tests.
- [ ] Capture exact test counts/build evidence from logs.

## Task 5 — Focused release review

- [ ] Compare `main` → final release HEAD; branch must be behind by 0.
- [ ] Confirm 54 skills / 11 active packs unchanged.
- [ ] Confirm no `skills/*/SKILL.md` files changed.
- [ ] Confirm 54 skill metadata + 11 pack metadata diffs are version-only.
- [ ] Confirm historical CHANGELOG entries were not rewritten.
- [ ] Confirm no temporary `.github/workflows/*` diff remains.
- [ ] Confirm no `v1.0.0` tag or GitHub Release exists yet.
- [ ] Update PR body with exact final HEAD and canonical CI evidence.
- [ ] Leave PR unmerged pending explicit user authorization.

## Post-merge publication boundary

Only after explicit merge authorization and the Stable PR is merged to `main`:

1. verify post-merge `main` CI on the merge commit;
2. create/publish `v1.0.0` from that verified `main` commit;
3. verify the GitHub Release/tag points to the intended Stable commit.
